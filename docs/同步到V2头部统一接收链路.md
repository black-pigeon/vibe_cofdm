# 同步到 V2 Header 的统一 FPGA 接收链路

## 已经接通的链路

当前 XC7Z020 参考顶层是 `cofdm_phy_rx_v2_top`。它把 ADC IQ、同步、回放、XFFT、双 LTF 信道估计、导频跟踪、均衡、LLR 和 V2 Header 解码连成一个有界流接口：

```text
ADC IQ
  -> STF 重复检测
  -> 粗频偏估计与 NCO
  -> TDM LTF 搜索/确认
  -> 环形 BRAM 回放
  -> XFFT 256 点、CP32
  -> 双 LTF 精频偏估计与补偿
  -> 双 LTF 频域信道估计
  -> Header/Data 导频公共相位校正
  -> 复数匹配滤波与软 LLR
  -> Header PRBS 解扰
  -> V2 BPSK 卷积码 TDM Viterbi
  -> CRC16/字段边界检查
  -> 释放 Payload LLR
```

主要 RTL 边界如下：

| 边界 | 模块 | 作用 |
| --- | --- | --- |
| 同步与捕获 | `cofdm_sync_ltf_cfo_top` | STF、粗 CFO、NCO、LTF 匹配、捕获状态机 |
| 有限回放 | `cofdm_pre_fft_stream_replay` | 用环形 RAM 保留训练/头部/数据所需样点，支持 Header 后续延迟续接；超过保留窗口时主动报错 |
| XFFT | `cofdm_fft_stream_frontend` + `cofdm_fft_256` | CP 去除、AXI-Stream XFFT、自然序 bin 和 TLAST |
| 精 CFO | `cofdm_ltf_fine_cfo_chain` | 双 LTF 频域相位差、CORDIC、NCO 相位增量 |
| 信道估计 | `cofdm_ltf_channel_chain` | `H=(Y1/T1+Y2/T2)/2`，输出 H RAM 和噪声方差 |
| 预 LDPC | `cofdm_phy_rx_v2_freq_top` | 导频相位、均衡、BPSK/QPSK LLR、载波重排、648 位码字边界 |
| Header | `cofdm_v2_rx_header_path` + `cofdm_v2_header_decoder_tdm` | Header 等待闸门、Viterbi、CRC16、版本/MCS/长度/seed/Midamble 校验 |
| 完整壳体 | `cofdm_phy_rx_v2_top` | 按符号重复回放；头部通过后按可变长度启动数据符号和 Midamble |

## 可变长度与延迟控制

V2 Header 通过后，硬件用 `payload_bytes` 计算 `ceil((8*payload_bytes+32)/324)` 个 LDPC 码字。码字数不是组合除法，而是每拍减去 324 的小状态机，最长 51 拍；在配置完成之前 Payload 闸门保持关闭。这条路径避免了 `payload_bytes → 大比较树 → packetizer` 的时序长路径。

Header TDM Viterbi 约需 6912 个 122.88 MHz 时钟（约 56.3 μs）。因此接收机先回放有限的 LTF/Header 前缀，头部解码结束后再从同一环形 RAM 的下一个符号重新开始。帧长度不会决定 RAM 深度；RAM 只保存捕获决策到当前回放指针之间的窗口。若写指针追上未读数据，`replay_error` 置位并丢弃帧。

当前完整壳体按一个 OFDM 符号启动一次回放，适合第一版验证和 Header 等待。后续若要提高吞吐量，应把“按符号重启”替换为“Header 后一次性延长回放”，并给 XFFT/预 LDPC 保留有界 FIFO。

```bash
  "addpath('matlab'); export_phy_rx_v2_vectors(257,25000,1)"
```

Icarus/Verilator 单元回归：

```bash

```

Vivado XSim 使用真实 XFFT IP、XPM FIFO 和 RAMB36E1 仿真模型：

```bash
/opt/Xilinx/Vivado/2022.2/bin/vivado -mode batch \
  -source matlab/vivado/cofdm_v2_header_ref/run_sim_full_top.tcl
```

## 现在还不能宣称完成的部分

Header/LLR 之后还不是完整数据接收机。剩余工作按优先级是：

1. **Payload LLR 解交织和 QC-LDPC 译码**：当前 packetizer 已给出 MATLAB 载波顺序和 648 位码字边界，但尚未把 LLR 交给 QC-LDPC 译码器。
2. **Payload 解扰与 PHY CRC32**：发送端是在 CRC32 后进行 Payload scrambling，必须在 LDPC 成功后解扰，再检查 CRC32 和填充位。
3. **Midamble 信道更新**：当前 Midamble 推进导频 PRBS，复用初始 H；高速移动场景需要用 Midamble 做低复杂度信道跟踪。
4. **多 MCS/码率**：当前 V2 只允许 profile 0、QPSK、LDPC(648,324)。其他 profile 必须通过 Header 字段选择不同 LLR 和 LDPC 参数。
5. **MAC/IP 交付**：Payload 译码成功后还需要 CRC、长度、帧序列和 AXI-Stream/TAP 接口，才能交给上层自组网协议。

因此，当前阶段可以准确表述为：**同步到 V2 Header 和 Payload 软信息已经形成可综合、可仿真的闭环；主 PHY 剩余核心是 Payload 的解交织、QC-LDPC、解扰、CRC 和帧交付。**

## 本次整链复核结论

当前顶层已经把 Header 解码接在前端软信息流上，而不是只做了两个模块的并列仿真：

```text
cofdm_phy_rx_v2_top
  ├─ cofdm_sync_ltf_cfo_top / cofdm_pre_fft_stream_replay
  ├─ cofdm_fft_stream_frontend (cofdm_fft_256 XFFT IP)
  └─ cofdm_phy_rx_v2_freq_top
       ├─ cofdm_ltf_channel_chain
       ├─ cofdm_pre_ldpc_stream
       └─ cofdm_v2_rx_header_path
            └─ cofdm_v2_header_decoder_tdm
```

`cofdm_v2_rx_header_path` 对 Header 和 Payload 使用同一个 ready/valid 边界。Header 符号先被 Viterbi 消费；`header_ok && crc_ok` 后才锁存长度、seed 和 Midamble 配置，并打开 Payload LLR 闸门。长度计算完成前，Payload 不会向顶层输出，因此非法头部不会把后端 FIFO 或 RAM 撑满。

在 2026-09-30 的 XC7Z020CLG400-2 / Vivado 2022.2 复核中，真实 MATLAB IQ 通过 XFFT 仿真输出：

```text
STF index=113
LTF peak index=256, score=65535
fine CFO increment=-537
Header ok=1, crc=1, payload_bytes=2048, seed=93, mid=1
PASS ... 33048 payload LLR signs
```

完整顶层综合报告为 11,789 LUT、11,553 FF、79 DSP48、15.5 BRAM Tile，122.88 MHz 下 WNS +0.208 ns、TNS 0。这个结果说明 Header 已经进入同步到 LLR 的可综合链路，但它不等于已经完成 Payload 数据恢复。

Header 之后仍有四类必须完成的工作：

1. 把 `payload_llr/payload_cw_first/payload_cw_last` 接入低并行 QC-LDPC 译码器，并用 BRAM 保存变量节点和校验节点消息。
2. 完成 LLR 解交织、LDPC 成功/失败状态和码字重试或丢帧策略。
3. 对译码比特做 Payload 解扰、CRC32、padding 和长度检查。
4. 将通过校验的数据写入有限深度 AXI-Stream/FIFO，产生真正的 `frame_done/frame_error` 和上层 MAC/IP 交付接口。

此外，当前壳体的 Midamble 仍只推进导频序列、复用初始信道；移动场景的信道更新以及“按符号重启回放”改成连续回放，属于吞吐量和高速移动优化，不应与 Header 解码完成混为一谈。
