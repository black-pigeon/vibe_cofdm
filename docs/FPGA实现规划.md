# Zynq-7020 FPGA 实现规划

本文件是实现预算和验证路线，尚无RTL综合/布局布线结果。不要将估计资源、时钟或吞吐当作已达成指标。

## 1. 平台与职责

XC7Z020标称PL规模约53,200 LUT、106,400 FF、140个36 Kb BRAM（4.9 Mb）、220 DSP48E1。应先扣除现有AD936x接口、DMA、AXI、调试和其他IP；本项目是否与检测逻辑共存需由完整Vivado工程确认。

- **PL**：实时采样、收发PHY、LDPC、CRC、时序与流控。高码率持续LDPC不能默认交给双核ARM。
- **PS**：配置、MCS/ARQ控制、包管理、统计与标定、网络/存储、测试脚本。
- 推荐逻辑目标122.88 MHz=8×Fs，是否能由实际参考时钟产生及7020速度等级时序通过待确认；ADC接口和AXI/DDR各自时钟域通过异步FIFO跨域。
- v0.1按TDD/半双工考虑FFT核复用；如果需要真正同时收发，必须增加FFT资源或完成双向合计吞吐和仲裁验证。

## 2. 模块与数据流

```text
TX: PS/DMA → payload FIFO → CRC32/PRBS → QC-LDPC encoder
    → codeword FIFO → bit interleaver → BPSK/QPSK mapper
    → carrier/pilot/training mux → 256 IFFT → CP insertion
    → gain/optional shaping → DAC interface

RX: ADC → DC/IQ front-end → STF correlator & packet FSM
    → coarse CFO NCO → LTF matched filter / fine CFO
    → symbol buffer → CP removal → 256 FFT
    → LTF/MID LS estimator → pilot CPE/slope tracker
    → equalization / matched-domain LLR → deinterleaver
    → codeword FIFO → layered QC-LDPC → descrambler/CRC
    → accepted-packet FIFO → DMA/PS
```

帧头与载荷共享LDPC核；训练符号从ROM读取。MID推进符号计数，但不推进载荷位地址。

## 3. FPGA 复杂度选择

| 模块 | 首选实现 | 需要验证的点 |
|---|---|---|
| STF相关 | D=16延迟线、64点滑动累加、能量比较 | 阈值可不用除法：|P|² > threshold E1E2；乘积位宽与溢出 |
| CFO相位 | 共享CORDIC按事件求角；NCO逐样本旋转 | 相位连续、Hz到相位增量换算、截断杂散 |
| LTF定时 | 串行复MAC复用或FFT相关 | 不能照MATLAB每个候选做256乘法而不算周期；192候选×256约49k复MAC，需并行/分级缩窗或缓冲后处理 |
| FFT/IFFT | 单核256点，流式或burst按预算选 | 288采样=2304逻辑周期；核总输入/计算/输出/重配置时间必须在预算内 |
| 信道LS | 单位模ZC除法变乘共轭 | 接收归一化尺度、LTF相位对齐、MID更新与双buffer切换 |
| 相位跟踪 | 8导频、共享CORDIC、加权累加 | 浮点unwrap/最小二乘改成相位连续和可控范围拟合；符号需缓存后再校正 |
| QPSK LLR | conj(H)Y + 噪声倒数缩放 | 首版可不为解调单独算MMSE除法；星座显示与LLR路径分开 |
| MMSE倒数 | LUT+一轮Newton或共享迭代除法 | 每符号200次倒数是否必要；静态H时可在训练更新时算 |
| CRC/PRBS | XOR/LFSR | 必须与本模型MSB、初值、补零除法一致 |
| 交织 | 乘13取模384地址生成 | 13=8+4+1，常数取模；384位RAM/FIFO即可 |
| QC编码 | 27位循环移位 + XOR | 特定矩阵结构，首校验块XOR求和，后续递推 |
| LDPC译码 | QC分层NMS，先27路展开评估 | α=3/4移位减法；bank冲突、最小/次小、符号积、迭代超时 |

LTF匹配是除了LDPC之外的关键捕获开销。建议先STF平台确定粗位置，再对稀疏候选粗搜，局部细搜；或复用FFT做线性相关。FFT相关需要足够零填充，不能把循环混叠峰当作帧起点。捕获可积累一帧到BRAM后处理，但应记录首包延迟与持续帧吞吐的区别。

## 4. LDPC 处理周期预算

矩阵Z=27，88个非空块，2376条边。假设每次迭代每个非空块需要读/更新两遍，P为并行提升因子通道数：

```text
C_iter_ideal = 2 × 88 × ceil(27/P)
```

| 并行数P | 单轮理想周期 | 12轮理想周期 | 122.88 MHz时间 |
|---:|---:|---:|---:|
| 1 | 4752 | 57024 | 464.063 μs |
| 3 | 1584 | 19008 | 154.688 μs |
| 9 | 528 | 6336 | 51.563 μs |
| 27 | 176 | 2112 | 17.188 μs |

这些不包括pipeline bubble、输入输出、syndrome、bank冲突。设计检查应使用实际RTL统计的周期，而不是只看此下界。

v0.1每687.5 μs需要译码16个载荷块+1个头块，平均每块40.441 μs / 4969.4逻辑周期。载荷符号连续期间每648位约31.641 μs产生一个块，低于平均预算，需码字队列吸收突发。

因此：

- P=9、12轮即使理想实现也超过平均预算，不能承诺持续满速。
- P=27作为推荐综合起点，12轮2112周期留出约2857周期做I/O和控制；最终仍需测量最坏路径。
- 每轮syndrome代价也要计入；可选择部分轮次检查以减少控制开销，但最大迭代预算不变。
- 不能依赖高SNR时一轮成功来证明实时性。必须保证全12轮的持续输入、队列满处理和丢弃策略。
- 若硬件容量迫使使用9路，需要减少轮数、降低持续速率或采用其他调度/更高时钟，并重新验证PER。

64QAM同长度数据区会产生48个载荷块+1头块，平均预算只剩1724.1周期/块；按当前88非空块工作量比较，同一个27路12轮核仅理想计算就无法满足。高码率要换校验矩阵，非空块数、层数和每层度数必须重新计算，不能直接把1/2码率核的周期当成最终实现。可选减少轮数、双核、更多跨块并行、提高时钟、码块重设计；每种都需资源/误码联合评估。

## 5. 存储和吞吐

| 项目 | 数据量 | 备注 |
|---|---:|---|
| ADC IQ，16+16位 | 61.44 MB/s | 单方向复数采样；双向122.88 MB/s，不含总线开销 |
| 双OFDM符号IQ缓存 | 2×288×32=18432 bit | 容量不大，端口/顺序决定bank数 |
| 一帧槽IQ缓存 | 10560×32=337920 bit | 容量约10个BRAM36，实际组织可能更多 |
| 8个软码字FIFO，LLR7位 | 8×648×7=36288 bit | 接近一个BRAM36容量；实际通常至少2块或按银行展开 |
| 单块后验9位 | 5832 bit | 648×9 |
| 单块边消息7位 | 16632 bit | 2376×7 |
| 单块输入LLR7位 | 4536 bit | 保留用于复位/重译码可选 |
| H，18+18位 | 200×36=7200 bit | 可双buffer支持MID原子切换 |

LDPC裸存储总量小，不代表一个BRAM就够。27路并行涉及27路读写和QC移位，可能采用按变量块分bank、部分寄存器/LUTRAM、地址旋转；必须把bank/交叉开关成本算进去。

建议包队列最少双buffer，码字队列初始8块；PS背压不得传播为ADC丢样后仍按完整帧译码。出现溢出时丢整帧、清状态、记录计数，不能静默错位。

## 6. 初始定点计划（待浮定点对照冻结）

后续局部验证已落实信道FIR的18位/14小数位数据、18位/16小数位系数及26位累加参考，具体舍入、饱和和对拍向量见 [局部定点与窗口优化](局部定点与窗口优化.md)。导频仅完成ROM系数量化；下表其他环节仍是待验证计划。

| 信号 | 初始位宽/格式 | 设计说明 |
|---|---|---|
| ADC原始 | 实际器件位宽，扩到16bit | 输入binary point由前端增益定义 |
| TX导出IQ | signed16，14小数位 | value=int/16384，范围[-2,2)，峰值/饱和有统计 |
| NCO相位 | 32bit模相位 | 15.36M采样下分辨约0.003576 Hz |
| 旋转系数/训练ROM | signed18，16或17小数位 | 明确1的表示与ZC量化误差 |
| 复数乘法累加 | 乘积全精度 + ceil(log2(W))保护位 | STF W=64至少再加6位；能量平方比较再扩展 |
| FFT输入/输出 | 16 / 18~20bit或block exponent | 使用IP缩放计划；避免256点FFT满增长直接截断 |
| 信道H | 18+18bit + 公共指数 | 深衰落不能被固定阈值插值覆盖 |
| LLR输入/边消息 | 7bit，2小数位 | 对称饱和±15.75；模型已有量化实验 |
| 后验/外信息 | 9bit，2小数位 | 对称饱和±63.75；溢出统计、舍入规则需RTL一致 |

初始建议保留0.2–0.5 dB浮定点性能预算，但这是验收目标而非实测损失。最终以PER曲线和饱和计数决定每处位宽。

浮点链路中对全部LLR做0.25～1.0比例缩放的筛查没有改变配对错误数；因此暂不增加独立缩放乘法器。定点阶段仍需将LLR缩放、饱和和归一化最小和消息位宽联合扫描，0.5候选可由算术右移实现。

## 7. 接口与可观测性

- IQ流采用AXI-Stream，固定约定I在低16位、Q在高16位；每个sample一次valid。CSV导出是I,Q两列，需要TB按该规则打包。
- `tuser`建议携带frame_start/symbol_kind/symbol_index/scale_exp/error；使用统一元数据FIFO保证不与数据错位。
- `tlast`按模块语义分别代表OFDM符号末、码字末、包末，转换点明确，不能混用。
- 控制寄存器：profile、增益、最大译码轮数、门限、帧序号、使能、复位。
- 统计寄存器：样本溢出、STF候选、LTF失败、CFO估计范围、头CRC失败、载荷CRC失败、译码轮数直方图、码字队列峰值、定点饱和。
- 控制更新采用帧边界生效；时钟域跨越用握手或异步FIFO，不逐bit同步多bit配置。

## 8. 初始资源包络

先给整个独立半双工PHY约20–35k LUT、25–55k FF、40–75 BRAM36、40–100 DSP的探索预算。该范围不是由综合获得，27路LDPC的布线/银行结构可能超出，需要早期原型核验证。至少预留约25%平台资源给接口和调试，并考虑时序拥塞；若与其他业务 bitstream 共存，必须重新预算。

不要在未综合LDPC和FFT前把整个方案固化。优先产出一个LDPC核的实际“LUT/FF/BRAM/Fmax/12轮周期”表，然后决定并行度和MCS上限。

## 9. 实施路线与验收门

当前已增加 MID 信道融合的可综合原型：`rtl/cofdm_mid_fusion_ctrl.sv` 负责 200 载波缓存、8 导频相关、创新门限和输出调度，`cofdm_quadrant_select.sv` 与 `cofdm_fusion_lane.sv` 为可复用内核。Icarus 仿真、Verilator lint 和独立 Python 整数向量检查均已通过；这不是 Vivado 资源或时序结果。接口、状态机和向量说明见 [RTL原型说明](../rtl/README.md)。

算法深化补充：接收机新增 `compact` 候选，优先以能量簇 FFT 窗、7 抽头移位加法 FIR、9 点导频搜索验证性能与定点损失，参见 [低复杂度接收机设计](低复杂度接收机设计.md)。该候选替代实验性大矩阵投影，不意味着下表的 RTL/综合阶段已经完成；需根据新的模块运算量更新调度，再冻结并行度。

| 阶段 | 交付 | 验收 |
|---|---|---|
| A 参数冻结 | PHY v0.1 + golden vectors | MATLAB/独立向量一致；字段和缩放无歧义 |
| B 核心预算 | QC编码、27路NMS原型、FFT IP | syndrome/码字bit-exact，最坏译码轮数和Fmax实测 |
| C 数字TX | 训练/头/数据映射、IFFT、CP | 与量化MATLAB符号/整帧对拍，PAPR/OOB测量 |
| D 数字RX | 同步/CFO/FFT/LS/导频/LLR | 各模块EVM、CFO误差、定时偏差和CRC检查 |
| E 定点整链 | 全链浮定点对照 | PER差异、饱和、背压/丢帧恢复 |
| E0 MID融合RTL | 200载波控制器与BRAM接口 | 逐周期向量一致；综合后Fmax、BRAM、DSP、LUT实测 |
| F SDR线缆 | 衰减器连接、异源时钟 | 灵敏度、频偏、持续吞吐、温度稳定性 |
| G 无线与ACM | 场景实测、增添MCS | 距离/速率/PER联合报告，不以单次连通为验收 |

可按2周模型与参数、2–4周核与定点、4–8周整链RTL/线缆验证作为初始排期假设；具体受已有IP、人员与RF硬件影响，不是工期承诺。
# Vivado 参考工程实测补充（XC7Z020CLG400-2）

已建立 `matlab/vivado/cofdm_mid_fusion_ref/`，并用 Vivado 2022.2 实际完成
XSim 仿真和综合。当前只对 MID 信道融合内核做实测，不把它等同于完整 PHY。

时序优化后的实测资源为 1142 LUT、617 FF、2 个 RAMB36、6 个 DSP48E1。
200×72 bit 的信道历史缓存和 256×37 bit 的结果 FIFO 均由 XPM 明确映射为
Block RAM。通过导频计算寄存器、末尾冲刷状态和 BRAM 输出后的 `FUSE_PREP`
流水级，122.88 MHz 虚拟时钟下 WNS 从 -1.168 ns 改善到 +0.733 ns，TNS=0。
该结果是综合级闭合；完整 PHY 集成后仍需重新进行 implementation 时序评估。

当前 Vivado 工程边界仍只有 MID 信道融合。同步、粗细频偏、FFT/CP、完整信道
估计、均衡、解调/解交织、LDPC、协议包头、AXI/ADC/射频接口尚未集成，MATLAB
模型或独立 RTL 检查通过不等于这些模块已经完成 FPGA 工程实现。
