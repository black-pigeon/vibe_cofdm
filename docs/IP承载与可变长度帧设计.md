# IP 承载与可变长度 PHY v2

日期：2026-09-28。目标：让PHY只处理传输必需信息，以有界的可变长度字节帧承载软件MAC及IP。v1固定644字节格式继续保留；v2为可运行的实验分支，尚不是定型空口协议。

## 1. 分层方案可行，但 IP 不替代无线 MAC

IP可以运行在自定义无线链路上，不需要空口复制以太网的电气层、前导或线速时序。以太网是二层链路协议，IP是三层网络协议。我们的链路可以向Linux提供网络接口，由软件完成路由和组网，PHY只传输不解释内容的字节串。

```text
应用 / TCP或UDP / IPv4或IPv6
          ↓
软件路由与邻居管理
          ↓
无线MAC：下一跳地址、接入、ACK/重传、去重、分片/聚合
          ↓
PHY服务数据单元：1～2048个不透明字节
          ↓
短PHY头 + 可变载荷 + LDPC / OFDM
          ↓
FPGA实时处理 / 射频
```

路由选择下一跳，MAC负责本跳的交付；节点发现、链路质量、超时和广播/多播也需要协议支持。碰撞、隐藏节点、半双工收发冲突不会因为采用IP而消失。

| 软件接口 | 交付内容 | 优点 | 额外责任 |
|---|---|---|---|
| TUN，建议首版 | IP包 | 三层多跳路由直接，不带以太网头 | IP下一跳到无线邻居映射、MAC封装、链路状态 |
| TAP/以太网式接口 | 以太网帧 | 便于二层工具与桥接接入 | ARP、IPv6邻居发现、广播开销、桥接环路和MAC地址管理 |

TUN不自动提供无线地址解析。TAP通常交付以太网MAC头和上层数据，不含以太网前导，通常不含网卡处理的FCS，仍须明确具体接口约定。当前PHY CRC32与以太网FCS的初值/位序约定不同，不能混用。

软件路由可评估Babel、OLSRv2等三层方案；二层Mesh也可选相应协议，但尚未集成。首版建议IP MTU1500、PHY最大服务单元2048，为MAC和可选安全信息留空间。必须满足“MAC头+IP包+附加信息≤PHY上限”。超限由链路适配分片/重组或调整MTU，不得静默截断；IPv6还需满足最小链路MTU等要求。

## 2. PS/PL 职责

| 功能 | 建议位置 | 约束 |
|---|---|---|
| IP、应用、路由、邻居表 | PS/Linux | 动态策略和网络栈 |
| 队列、下一跳、重传策略 | 软件MAC为主 | 可迭代、可观测 |
| 精确定时TX、时间戳、收发切换 | PL实时控制 | 不依赖普通Linux线程的微秒级调度确定性 |
| ACK截止时刻、时隙边界 | 软件策略+硬件执行 | 依选定接入协议落实 |
| IQ、同步、FFT、纠错、帧交付 | PL PHY | 持续吞吐和有界延迟 |

当前没有TUN/TAP驱动、MAC或定时TX状态机。v2只先建立字节服务接口。“软件执行组网”不意味着Linux用户态逐样本或逐微秒控制射频。

## 3. 1符号短 PHY 头

固定1个OFDM符号：192数据载波BPSK，另8载波仍为导频。字段MSB优先，头部格式不随载荷MCS改变。

| 字段 | 位数 | 定义 |
|---|---:|---|
| version | 4 | 必须为2 |
| mcs | 4 | 目前只接受0：QPSK、LDPC(648,324)、1/2码率 |
| payload_bytes | 12 | 服务单元长度1～2048，不含PHY CRC32/填充 |
| scrambler_seed | 7 | 载荷PRBS7种子1～127 |
| midamble_code | 2 | 0→每8数据符号，1→每4，2→每16；3保留并拒绝 |
| reserved | 3 | 必须为0 |
| CRC16 | 16 | 校验前32位字段，沿用工程CRC约定 |

```text
32位字段 → CRC16 → 48位 → 追加6位尾零
→ K=7、1/2卷积码 → 108位
→ 编码外补84位至192位 → 固定头扰码 → BPSK
```

卷积码多项式按八进制 `[171,133]` 顺序输出，寄存器为 `[当前输入,之前六位]`，新输入位于最高位，下一状态为七位寄存器右移1位。初始/终止状态均为零。软Viterbi一定能找到路径，因此仍必须检查CRC与字段合法性。全部192位使用种子31扰码，避免填充产生大量同相BPSK。

PHY头不放节点地址、网络ID、业务序号、ACK标志或路由字段；这些属于载荷中的MAC头。码字数也不发送，由长度/MCS推导，避免冗余字段不一致。seed和MID字段用于接收端解扰和训练日程，属于物理层配置。

当前108个编码位顺序映射到数据载波，其余84位只是填充，没有额外纠错贡献，也尚未进行头部频率交织。后续优先比较重复编码位并合并LLR、跨频率交织等低复杂度方案，再根据头失败率决定是否需要更强保护。缩短头部不等于已经改善其低SNR性能。

MAC头建议另行定义版本/帧类型、网络标识、源与下一跳地址、序号、ACK/分片标志、上层协议标识等字段；位宽需结合节点规模与接入方案冻结。它和IP包一起属于PHY载荷，不额外增加固定PHY头符号。首版采用“一帧一个MAC PDU”，后续若聚合多个IP包，则在MAC载荷内部增加子包长度；PHY的总长度字段不能代替聚合子包边界。

## 4. 可变载荷与两层填充

设服务单元长L字节：

```text
Ncw     = ceil((8L + 32) / 324)
Pinfo   = 324*Ncw - (8L + 32)
Ndata   = ceil(648*Ncw / 384)
Psymbol = 384*Ndata - 648*Ncw
Nmid    = floor((Ndata - 1) / midambleEvery)
```

发送顺序：L字节→CRC32→补Pinfo个零→对全部信息区扰码→Ncw次LDPC→追加Psymbol个PRBS填充位→按384位组符号→交织/QPSK。

- 信息填充属于LDPC输入，参与编码；解扰后必须为零。CRC只覆盖原L字节，不包括填充。
- 编码外符号填充不属于码字，采用种子47的PRBS；接收机丢弃这些LLR，不送LDPC。

接收机先解扰完整Ncw×324信息区，再取前8L+32位做CRC及字节恢复，检查剩余零填充。不能把含填充的信息区长度当成上层包长。不同长度的相邻帧不需要更换FFT或LDPC矩阵，只更新计数器。

## 5. 开销与最大处理边界

Fs15.36MS/s、FFT256、CP32、STF160点、双LTF和8导频不变。MID周期8时：

| 载荷字节 | 码字 | 数据符号 | MID | 槽长μs | 理想PHY载荷Mbps |
|---:|---:|---:|---:|---:|---:|
| 1 | 1 | 2 | 0 | 106.25 | 0.075 |
| 36 | 1 | 2 | 0 | 106.25 | 2.711 |
| 64 | 2 | 4 | 0 | 143.75 | 3.562 |
| 644 | 16 | 27 | 3 | 631.25 | 8.162 |
| 1500 | 38 | 65 | 8 | 1437.5 | 8.348 |
| 2048 | 51 | 87 | 10 | 1887.5 | 8.680 |

槽长含32点GUARD，不含接入、TDD换向、ACK、重传和队列。更密MID会变长；当前最大布局为2048字节、MID周期4，共32160样本、2093.75μs。

与v1同载荷644字节、同MID周期相比，省去3个头符号，即56.25μs。短包仍受前导和至少一个LDPC码字限制；ACK专用短帧、短码或聚合应另开profile研究，不能声称所有长度都高效。

## 6. 有界接收流程

1. 仅凭1024采样点的固定前导+头前缀进行捕获，不预先要求知道整包长。
2. 同步、H估计和头BPSK软解调，进行108位Viterbi。
3. 检查CRC16，再验证版本、唯一支持的MCS、1～2048长度、非零seed、MID及保留位。
4. 通过后才推导码字/符号数量和样本末端，检查capture是否完整，再分配载荷数组。
5. 接收载荷/MID，反交织、LDPC、解扰、零填充与CRC32全部满足才 `r.ok=true`。

CRC不是身份认证。有效CRC但非法长度/MCS也必须拒绝，未来RTL还要增加流式超时和接收预算。CRC16采用非反射0x1021、零初始/末异或，不能直接使用任意CRC库默认项；CRC32也不等于以太网FCS。

## 7. FPGA 增量开销

头不再使用LDPC，但新增64状态Viterbi。54个trellis步×64状态=3456次两路ACS择优。若每状态每步存一个选择位，幸存路径为3456bit，另加路径度量、归一化及回溯逻辑。MATLAB参考存uint8前驱状态便于理解，不等于最终RTL存储格式。

Viterbi目前是浮点参考，尚未冻结度量位宽、LLR饱和和ACS并行度。不能把3456bit当作完整Viterbi资源，或假定它一定优于共享LDPC核。

载荷固定648位核继续复用，最大51个码字。流式实现不必存整包LLR，但需覆盖头译码延迟和码字到达突发。PL应独立解析已支持的PHY字段并更新计数器，不依赖PS在短头结束到首数据符号间及时响应。

## 8. 软件接口与兼容性

TX描述符建议包括缓冲地址、有效长度、MCS/训练配置、队列及定时发射请求。下一跳/MAC序号在payload中，PHY不解析。RX描述符建议包括实际长度、成功标志/原因、经定义的硬件时间戳、MCS及译码/质量统计。多径最强峰位置不能直接当作校准过的传播时间。

```matlab
addpath('matlab');
result = run_variable_demo(1500);
txConfig = cofdm.config_v2('compact');
rxConfig = cofdm.config_v2('compact'); % 不需要TX长度、seed或MID配置
code = cofdm.ldpc_code();
payload = uint8(0:99).';
[wave,meta] = cofdm.tx(payload,0,txConfig,code);
% seq参数在v2必须为0；业务序号放在MAC payload。
% y = cofdm.channel(wave,txConfig,p);
% r = cofdm.rx(y,rxConfig,code);
```

`config()`仍选v1，`config_v2()`显式选v2。TX布局在 `meta.config`，头验证后的RX布局在 `r.frameConfig`；v2没有v1的PHY序号字段。

两个版本前导相同而头编码不同，当前不支持盲判自动兼容。双方必须事先选择同一格式；version是在选定头译码器之后校验的，不能靠该字段自动决定先用LDPC还是Viterbi。未来共存须外部协商或可靠格式识别设计。

新增实现为 `config_v2 / frame_layout / header_trellis / header_conv_encode / header_viterbi / header_v2`，其余OFDM、信道估计和载荷LDPC继续共享。真实TUN/TAP、MAC、IP栈集成和路由尚未实现；演示传输任意字节，不代表已经联网。

结果见 [v2验证记录](../results/VARIABLE_PHY.md)。一符号短头是候选，需继续用低SNR头失败率、虚警及定点/硬件结果定型。
