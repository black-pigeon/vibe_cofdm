# COFDM 分级捕获设计

## 为什么 STF 不能直接锁定

STF 的重复结构适合快速发现突发、估计粗频偏和唤醒后级逻辑，但窄带连续波、周期性干扰、其他 OFDM 帧、AGC 瞬态和多径相关平台也会产生相似的周期相关峰。因此 `stf_hit` 在本系统中定义为候选事件，而不是“收到有效包”。

## 接收机捕获链

```text
滑动 STF 相关/能量门限
        │ stf_candidate
        ├── 粗 CFO 角度估计
        └── 候选窗口
              │
              ▼
      已知双 ZC-LTF 相关
      峰值、位置、能量归一化
              │ 合法且足够强
              ▼
      两个 LTF 细 CFO/信道估计
              │ fine_cfo_valid
              ▼
      FFT → 均衡 → PHY Header 解调
              │ Header CRC OK
              ▼
      frame_valid / capture_locked
```

`cofdm_capture_ctrl.sv` 只负责时序和判决，不实现 256 点相关或 LDPC。状态为 `IDLE → LTF_SEARCH → FINE_WAIT → HEADER_WAIT → LOCKED → HOLDOFF`。每个等待状态都有超时；错误候选计入 `false_alarm_count`，进入保持窗防止同一干扰或同一帧产生重复事件。

## 推荐的门限与窗口

- STF：相关系数门限先由噪声和误警率扫描确定，使用能量门限、连续命中次数和滞回；不要使用整段捕获最大能量这种非因果门限。
- LTF：在 `stf_index + 64 ... + 384` 的窗口内搜索，使用 `|rᴴt|²/(E_r E_t)` 归一化分数；位置必须落入合法范围。默认 Q0.16 分数门限为 0.12，需通过实测信道重新标定。
- Header：CRC 是最终捕获确认。仅有 STF 或 STF+LTF 不能向 MAC 层报告有效帧。

## FPGA 资源策略

控制器仅使用比较器、加法器、计数器和少量寄存器；LTF 相关器应采用 256 点 FFT 后的有效子载波相关，并逐拍复用 DSP，避免在捕获阶段展开 256 个复乘器。候选窗口和相关峰值只保留最大值及其位置，数据通过 FIFO/BRAM 送往后级。

当前 XC7Z020 综合结果（STF、NCO、CORDIC 加分级控制器）为 LUT 2116、FF 2171、DSP48E1 29、BRAM 0；122.88 MHz 时钟下 WNS +2.324 ns、TNS 0。该结果只代表前端和捕获控制，不代表完整 FFT、均衡或 LDPC PHY 已完成。

## 验证覆盖

MATLAB `tests/run_capture_false_alarm_tests.m` 和 RTL `tb/tb_capture_ctrl.sv` 覆盖正常帧、STF-only、弱/非法 LTF、错误 Header、锁定后结束和保持窗。后续应把 AWGN、单音、周期性窄带干扰、多径、STF 截断和相邻帧波形接入同一事件接口，统计候选检测率、LTF 确认率、Header 确认率、最终误锁率和捕获时延。
